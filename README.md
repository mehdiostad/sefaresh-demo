# سفارش آنلاین — دموی بازسازی‌شده

این پروژه نسخهٔ دموی بازسازی‌شدهٔ سیستم مدیریت کافه و منوی دیجیتال سفارش آنلاین برای ارائه در رزومه است. **سرویس اصلی دیگر فعال نیست.**

ظاهر و کامپوننت‌های اصلی پروژه حفظ شده‌اند. منوهای کافه علم، کالما و ماریا از فایل‌های ارسالی استخراج شده و اطلاعات مشتریان، سفارش‌ها، گزارش‌ها و باشگاه مشتریان نمونه‌اند. در دمو پیامک، پرداخت، آپلود ابری و اتصال به دیتابیس واقعی وجود ندارد.

## استقرار روی Vercel

1. ZIP را استخراج کنید. **محتویات پوشهٔ `sefaresh-demo`** را در یک repository جدید GitHub قرار دهید؛ `package.json` باید در ریشهٔ آن باشد. پوشه‌های `node_modules`، `.next` و `.next-dev` را آپلود نکنید.
2. در Vercel، **Add New → Project** را بزنید و repository را **Import** کنید.
3. Framework Preset: **Next.js**. اگر کل پوشه را به‌صورت زیرپوشه آپلود کرده‌اید، Root Directory را همان پوشه‌ای بگذارید که `package.json` در آن است.
4. Node.js: **22.x**. Build Command: `npm run build`. Install Command: `npm ci`. Output Directory را روی مقدار پیش‌فرض Next.js بگذارید؛ `out` یا `dist` تعیین نکنید.
5. **Environment Variables خالی است**؛ MongoDB، NextAuth، Pusher، SMS، Zibal یا Arvan را تنظیم نکنید. پروژه فقط دمو است.
6. **Deploy** را بزنید. پس از آماده شدن، آدرس تولیدی دامنهٔ `vercel.app` را باز کنید و `/dashboard` و هر سه مسیر `/cafe_elm`، `/cafe_calma` و `/cafe_marya` را امتحان کنید.
7. برای اینکه کارفرما بدون ورود به Vercel دمو را ببیند، دسترسی **Production** نباید به حساب Vercel محدود باشد. تنظیمات Deployment Protection را بررسی کنید. لینک اصلی Production را در رزومه قرار دهید، نه لینک build log یا داشبورد Vercel.

برای استقرار از کامپیوتر خودتان، روش جایگزین CLI است:

```bash
npx vercel
npx vercel --prod
```

این دستورها را داخل پوشهٔ پروژه اجرا کنید؛ احراز هویت حساب Vercel را خودتان تکمیل کنید. تنظیمات داخل `vercel.json` آماده است. این فایل ZIP هنوز روی Vercel منتشر نشده است.

## داده‌های دمو و ماندگاری

- `src/demo/menu-calma.json`: ۶ دسته و ۳۳ آیتم کالما؛ برای ۶ قهوهٔ موجود که قیمتشان در خروجی صفر بود، قیمت نمونهٔ مشخص‌شده با `demoPrice` قرار داده شده است. قالب `cafe_calma` موجود در پروژه.
- `src/demo/menu-marya.json`: ۵ دسته و ۴۲ ردیف از فایل اصلی ماریا؛ در دموی عمومی ۳ ردیف آشکارا آزمایشی حذف شده و ۳۹ آیتم نمایش داده می‌شود. رنگ پایه و مسیر پس‌زمینه‌های `CafeMarya1.jpg` تا `CafeMarya5.jpg` از کامپوننت‌های قدیمی ماریا حفظ شده و به منوی مشترک فعلی متصل شده‌اند.
- `src/demo/menu.json`: ۱۰ دسته و ۷۱ آیتم کافه علم، با نام فارسی، توضیح، قیمت، موجودی و ترتیب ارسالی. برای **تمام ۷۱ آیتم** مقدار انگلیسی `secondItemName` اضافه شده است؛ نام‌های انگلیسی بازسازی‌شده‌اند.
- دادهٔ اولیهٔ داشبورد شامل ۶ مشتری ساختگی و سفارش‌های نمونهٔ ۳۰ روز اخیر است. بازدیدها و نمودارهای آماری شبیه‌سازی هستند.
- افزودن/ویرایش/حذف دسته و آیتم، جابه‌جایی، تغییر موجودی، سفارش، تغییر وضعیت سفارش، تنظیم وفاداری، دریافت جایزه و کوپن روی داده‌های همین مرورگر انجام می‌شود.
- وضعیت علم در `localStorage` با کلید `sefaresh-resume-demo-v1` و وضعیت کالما و ماریا با پسوند `:cafe_calma` و `:cafe_marya` نگهداری می‌شود و پس از refresh باقی می‌ماند. دو تبِ یک کافه از همان مرورگر دادهٔ مشترک دارند؛ کافه‌ها، مرورگرها و بازدیدکنندگان مختلف مستقل‌اند. نشست مشتری و سبد سفارش هنگام تغییر کافه با منوی کافهٔ دیگر مخلوط نمی‌شود. داشبورد پیش‌فرض همچنان برای کافه علم است.
- گزارش‌های فروش و آیتم‌ها از سفارش‌های نمونه محاسبه می‌شوند و فیلتر تاریخ را رعایت می‌کنند. اگر مدت زیادی از اولین بازدید گذشته و گزارش اخیر خالی است، `/demo/reset` را باز کنید تا نمونه‌های جدید ساخته شوند.
- آپلود تصویر فقط در مرورگر ذخیره می‌شود؛ محدودیت هر تصویر ۲ مگابایت است. در صورت غیرفعال بودن یا پر شدن حافظهٔ مرورگر، تغییرات فقط در حافظهٔ موقت باقی می‌مانند.
- HTTP API فقط دادهٔ نمونهٔ اولیه را برای GET برمی‌گرداند؛ تغییرات و نشست مشتری عمداً در مرورگر شبیه‌سازی می‌شوند و سرور ذخیره‌سازی مشترک ندارد. این راهکار برای دمو است و احراز هویت production محسوب نمی‌شود.

## تصاویر اصلی: محدودیت فایل ارسالی

تصاویر تزئینی کالما در مسیرهای اصلی `public/themes/cafe_calma/` به‌صورت شفاف جای‌نگهداری شده‌اند تا بعداً با فایل‌های اصلی جایگزین شوند. پس‌زمینه‌های ماریا فعلاً همان رنگ پایهٔ قهوه‌ای موجود در کد قبلی را دارند. لوگوهای اصلی کالما و ماریا ارسال نشده‌اند و برایشان برند یا لوگوی ساختگی تولید نشده است.

**ZIP ورودی پوشهٔ `public` نداشت.** بنابراین تطابق پیکسلی همهٔ تصاویر با سرویس قبلی هنوز ممکن نیست.

- لوگو، متن و پس‌زمینهٔ کافه علم از SVGهای موجود در `src/Icons.js` بازیابی شده‌اند.
- عکس آیتم‌ها، اسکرین‌شات‌های صفحهٔ اصلی و برخی تصاویر قدیمی موجود نبودند. به جای ادعای عکس اصلی، از جای‌نگهدار با عبارت `Demo · original image not supplied` استفاده شده است.
- ساختار JSX، کلاس‌ها، فونت‌های موجود، اسلایدر، دیالوگ‌ها، رنگ‌بندی و قالب‌ها بازطراحی نشده‌اند. فقط اتصال داده/نشست، متن‌های مرتبط با دمو، مسیر تصاویر و سازگاری اجرا اصلاح شده‌اند.
- برای بازگشت کامل تصاویر، پوشهٔ `public` اصلی را روی این پوشه قرار دهید. نام فایل‌های عکس آیتم‌ها در `src/demo/menu.json` حفظ شده است؛ عکس‌ها را در `public/items/` یا `public/demo-assets/items/` بگذارید. اگر قبلاً در فضای ذخیره‌سازی خارجی بودند، خود فایل‌های آن فضا نیز لازم است.
- لوگوهای مشتریان در `public/demo-assets/userLogos/` قرار می‌گیرند. برای لوگوی اصلی کافه علم نام مسیر در `src/demo/seed.ts`، فیلد `menuLogo` است؛ در صورت تفاوت نام، همان فیلد را تغییر دهید.

## اجرا و بررسی نسخهٔ Production

```bash
npm test
npm run typecheck
npm run build
npm start
```

تست‌ها شامل جداسازی منو، نشست و سفارش کافه‌های مختلف، نام‌های انگلیسی، رد کد اشتباه و پذیرش ارقام فارسی، CRUD و استقلال بازدیدکنندگان، سفارش و چرخهٔ کوپن/امتیاز، دریافت جایزه، تطبیق گزارش و فیلتر تاریخ، شبیه‌سازی اشتراک و بازنشانی هستند.

نسخهٔ Next.js به `15.5.28` ارتقا یافته و پارامترهای مسیر و cookies با آن سازگار شده‌اند. React و کامپوننت‌های ظاهری پروژه حفظ شده‌اند. `package-lock.json` برای نصب قابل تکرار همراه پروژه است. هشدارهای غیرمسدودکنندهٔ قالب اصلی دربارهٔ hook dependencies و تصاویر باقی مانده‌اند.
